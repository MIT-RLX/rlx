# rlx-signal

The parts of SciPy 1.17.1's `scipy.signal` that EEG/fNIRS pipelines run (MNE's
`raw.filter`, TDDR, SCI), reproduced **bit-for-bit** on the macOS arm64 reference
build.

| module | functions | SciPy |
|---|---|---|
| `iir` | `buttap`, `lp2lp_zpk`, `lp2hp_zpk`, `lp2bp_zpk`, `bilinear_zpk`, `butter_zpk` | Butterworth design |
| `iir` | `zpk2tf`, `zpk2sos`, `cplxreal`, `poly` | format conversion |
| `iir` | `lfilter`, `sosfilt`, `lfilter_zi`, `sosfilt_zi`, `filtfilt`, `sosfiltfilt` | filtering, initial conditions, zero-phase |
| `fir` | `firwin`, `get_window`, `general_cosine`, `np_sinc` | FIR design and cosine-sum windows |
| `complex` | — | NumPy's `complex128` arithmetic, rounded as NumPy rounds it |

## Why the spelling matters

SciPy's inner loops are C/Cython, and NumPy's complex ufuncs are C, both compiled
by clang with `-ffp-contract=on`: `a*b + c` in one expression is one FMA. So:

* the two filter loops are SciPy's expressions in Rust, with an FMA exactly
  where clang fuses (no C is compiled);
* the complex helpers say which product is fused;
* `lfilter_zi`'s linear solve goes through `rlx-cpu`'s `dgesv_numpy`, the LAPACK
  call NumPy makes.

Tests compare bit patterns against vectors generated by SciPy
(`tools/gen_vectors.py` → `tests/vectors/`).
